# 分析指引

## 固定本次依据

为关键事实编号 `E1`、`E2`…，记下来源、发言人、日期和可回查位置（时间戳、行号、页码、段落或 CRM 记录）。分开五类：

| 类别 | 写法 |
| --- | --- |
| 买方表态 | 有原文才用引号；速记里的买方意思写成转述。 |
| 我方承诺 | 写明承诺人、内容和期限，这是首要动作的第一来源。 |
| 销售转述 | 标为销售转述，不当作买方确认。 |
| CRM 字段 | 阶段、金额、成交日等只说明系统记录。 |
| 推断 | 写明依据，不写成事实。 |

同一事项前后冲突时并列记录，优先生成澄清问题。职位、参会和 CRM 角色分别只证明各自的事，不证明预算权或决策权。

## 用 POWERFUL 找问题

POWERFUL 只用来找要问的问题，不打分、不算赢率，也不作为第二套评估框架。逐维看缺什么，转成具体问题，分配给最能回答的角色。

| 维度 | 要弄清的事 | 示例问题 |
| --- | --- | --- |
| P 痛点 | 客户确认的问题、发生在哪里 | 最近一次出问题是哪道工序、什么情况？ |
| O 机会成本 | 不解决的代价、时间压力 | 继续现在的做法，下个季度会影响什么？ |
| W 需求 | 必须满足的条件、验收方式 | 怎样算通过？谁认可这个标准？ |
| E 高层影响力 | 谁发起、谁批准推广 | 试点通过后由谁决定推广、需要什么材料？ |
| R 资源与预算 | 预算归属、人力、环境和资料 | 推广的预算归哪个部门？验证需要的模型和环境谁能提供？ |
| F 失败顾虑 | 客户最怕出什么问题 | 哪些产线、时间段或数据不能受影响？ |
| U 信任 | 客户还需要看到什么才相信 | 需要看到哪些结果或失败样例，才愿意进入下一步？ |
| L 执行细节 | 下一个会、参与人、材料和日期 | 评审安排在什么时候、谁参加？ |

证据状态沿用商机复盘的说法：有证据、待核实、缺失、不利。已确认的坏消息仍是风险。

## 选出首要动作

先兑现已作出的我方承诺。客户接受现状或明确暂缓时，可结束本轮或等买方约定的条件出现；无需另约日期或索取引荐。影响尚不清楚、客户愿意交流时，只问一个能改变决策的问题。影响已确认时优先核实现有流程或配置能否达标。只有买方愿意解决仍存在的缺口，才安排相应范围的试点或推进动作。

决定推进后按以下顺序选：

1. 已到期或将到期的我方承诺。
2. 阻碍买方下一个决定的前置条件，例如样件许可、准入流程、验收口径。
3. 推进到下一个决策环节需要的人或材料，见[产品参考](products.md)。

每项动作写明执行人、对象、时机、希望看到的结果，以及没达成时的替代动作。可以并行的标明并行。建议日期标「建议」，客户没承诺的负责人或时间写「待确认」，不和买方承诺混写。

## 目标承诺与退一步承诺

推进时定一项**目标承诺**：买方的谁、做什么、什么时候。必须是能观察到的行动，例如「陈工 11 月 25 日前提供两套历史模型」；「客户认可方案」「保持沟通」不算。

再定一项**退一步承诺**，在目标承诺拿不到时争取，例如「先确认谁有权提供模型」「先批注不能占用的时间窗口」。

承诺按产品和决策环节选，见[产品参考](products.md)。

## 根据回应调整

只用当前会话可见的客户回复和上一轮材料。用户没有提供上一轮计划时，按现有材料重新判断，并说明依据范围。只记录回复实际确认的事。

| 回应 | 调整 |
| --- | --- |
| 接受 | 记录确认的内容，首要动作推进到下一步，目标承诺换成下一个环节的承诺。 |
| 附加条件 | 把条件拆成新的前置动作，判断是否影响顺序，例如准入是试点前置时前移采购核实。 |
| 拒绝或暂缓 | 接受客户决定。已有约定按约执行；没有重启条件时结束本轮。 |
| 只回「收到」 | 只说明送达，首要动作不变。 |
| 未回复 | 首要动作改为跟进；约定日期前不催，过后用未回复跟进邮件。 |

需要判断整笔商机的阶段、预测或赢率时，转商机复盘 Skill。
