# 角色模板

以五类角色为起点，按本轮要验证的业务流程确定参与人。PLM 涉及系统接口时请信息化负责人参与。QMS 按来料、制程、客诉、质量策划或体系审核选择归口人。渠道商机写明由谁报价、由谁作出承诺。已知姓名就写姓名，未知时写岗位或引荐路径。见[产品参考](products.md)。

| 角色 | 通常要弄清的事 | 常见目标承诺 |
| --- | --- | --- |
| 业务负责人 | 痛点、时间压力、谁参与评审 | 协调评审时间和参与人，引荐下一位。 |
| 技术评估人 | 验收标准、验证方式、谁认可结果 | 确认通过标准，提供验证环境。 |
| 使用者 | 真实场景、典型样件、使用限制 | 选出典型样件，说明使用条件。 |
| 采购 | 准入、流程、负责人和周期 | 说明流程和周期，是否为前置条件。 |
| 预算批准人 | 推广条件、预算归属、评审时间 | 确认决策条件和下一次评审。 |

## 排序

1. 能兑现我方承诺、能打通下一个环节的人先见。
2. 采购或预算如果是当前环节的前置条件，立即前移，与技术验证并行。
3. 没有直接联系的角色，先请已接触的人引荐，不越过对方直接联系。
4. 图谱或公司级查询找到的人，列为待核实候选，先请求引荐。

## 访谈提纲

需要推进的访谈写：本次目标、目标承诺、退一步承诺、两三个问题、要带的材料。问题优先补[分析指引](analysis.md#用-powerful-找问题)里缺失的维度，追问谁负责、什么时候、怎么确认。

逐人写出沟通目的、一句对该人可直接使用的请求、触达时机或前置条件、已知联系人或引荐路径。明确每次联系要解决谁的哪项决定。示例：技术已认可时，请技术接口人确认验收记录可否供内部评审；采购未入场时，请业务联系人先核实准入是否为前置；预算批准人未知时，请发起人说明审批路径，待引荐后再约谈。
