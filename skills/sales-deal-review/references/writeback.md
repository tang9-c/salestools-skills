# 上传与回写

## 先检查本轮权限

用户已明确要求上传附件及实际回写时，用一次 `connect_zoho` 同时传 `attachmentUpload: true, writeback: true`。只要求其中一项时仅传对应参数。先核对当前在线 schema。用户只要求复盘或只看预览时，按只读权限核对。用户看完复盘后才决定执行时，在给上传链接或回写预览前检查新增权限。

若返回 `connected`，直接继续。若返回一次性链接，仅请用户打开「继续连接 Zoho」并按页面提示操作，上传页和预览页应在同一浏览器环境中打开。浏览器会话丢失时，同一次调用带上 `browserLogin: true` 和当前所需权限。有效个人授权会直接恢复会话，缺少对应权限时由页面引导授权；临时故障时提示稍后再试。恢复后优先刷新原页面。

## 上传 CRM 原件

根据已定位的商机调用 `open_deal_review_upload`。回包声明 `directUpload: true` 时，回复「到〔上传附件〕选好文件，点『上传到 Zoho』」。页面负责暂存、提交、续传和展示结果，避免要求用户从浏览器复制原件编号或操作编号。用户尚未确认页面结果时，只能说「已打开上传入口」。用户需要核对时读取商机附件列表，区分已确认附件与无法核实的结果。页面提示结果待核实时，先查 Zoho 附件列表，不让用户重新选同一文件上传。

旧部署的在线 schema 没有 `attachmentUpload` 时，只传其支持的参数。旧上传页仅支持暂存时，沿用原有上传接口、实际浏览器回执和稳定操作编号。普通使用时以状态和文件名为主，排障时才让用户打开「查看详情」。原件上传不等待内容解析，复盘取证继续使用[客户端解析](file-evidence.md)。

## 字段和备注的确认

用户要求准备 CRM 回写时，使用当前会话中已核验的复盘。仅提议更新阶段、金额、赢率和预计成交日。MCP 请求中为每个修改提交理由、证据 ID 或经理明确输入，并标明 `evidence` 或 `manager_input`；经理来源保留其实际输入。不填无依据的值，不把 MEDDPICC 评级当赢率，不猜阶段或自动通过 Blueprint。

| 用户要改的字段 | Zoho API 字段 | 预览前核对 |
| --- | --- | --- |
| 阶段 | `Stage` | 使用当前布局和管道中允许的实际阶段值。遇到 Blueprint 约束时按服务端提示处理。 |
| 金额 | `Amount` | 使用商机现有币种，核对币种和金额。 |
| 赢率 | `Probability` | 确认详情返回独立字段。若同时更新阶段，核对该管道的联动赢率。 |
| 预计成交日 | `Closing_Date` | 使用 `YYYY-MM-DD`。 |

用同一 `reviewId` 最新详情的 `deal.visibleFields` 核对原值。搜索回包、页面标签和阶段名里的数字都不能证明字段可回写。发现字段不支持或当前详情不可见时，先指出受阻项，请用户确认是否仅为其余字段生成预览。自定义字段即使键名相同，在不同布局和组织中也可能代表不同含义，只能使用在线工具明确支持的 API 字段。服务端会进一步核对记录状态、布局、字段与当前人的权限。字段可见但服务端拒绝回写时，说明具体阻塞，经用户确认再缩小范围重新预览。

仅写 Notes 时提交 `changes: []`。若经理明确给出要写入的原文，且在线 schema 声明 `managerNote`，将原文逐字填入 `managerNote`，同时在校验包的 `confirmations.managerNote` 中记录该输入。摘要仍通过 `noteClaims` 和证据 ID 提交。受限内容或共享范围未知的材料及其衍生判断不得改填到 `managerNote`。仅重试备注时须重新提供同一原文。

从当前在线 schema 构造 `prepare_deal_review_writeback`。普通预览提交 `mode:new`、`reviewId`、`changes` 和可选 `noteClaims`。仅提交拟作为 Zoho 摘要的简短判断及其 CRM 证据 ID。完整复盘和文件摘录留在会话中。预览注明实际变化、业务理由和排除来源。共享范围受限或未知的证据及其衍生判断排除在 CRM 备注之外。收到预览后给经理返回在线确认链接，说明备注将按 Zoho 备注权限共享。如需恢复会话，沿用前面的连接步骤。授权版本未变且预览仍有效时，刷新原预览即可。重新授予了个人权限或预览已经失效时，重新生成预览。若工具返回 `REVIEW_WRITEBACK_DISABLED`，告知经理当前环境仅支持预览与记录确认。经理在浏览器核对后一次确认；修改建议需重新生成预览，撤销或过期则按页面提示处理。

预览成功只进入待确认。用户完成确认后，以浏览器回执核对字段写入、回读和备注结果。若备注明确失败且字段已成功或无需更新，按页面指引重试。需要重新预览时，提交 `mode:retry_note`、浏览器回执中的 `operationId` 和原 `noteClaims`，再交给经理确认。发送中、结果未知或字段未核实时应先核查，避免重复写入。确认操作由浏览器中的经理完成。

向经理展示的示例：

- 「示例商机现在是提案，金额 36 万元，预计成交日期是 2027-03-31。你想改哪些字段，备注写什么？」
- 「附件已上传。备注预览也准备好了，请打开〔查看并确认〕核对。」
- 「附件已上传，备注已写入，商机字段保持原值。」
