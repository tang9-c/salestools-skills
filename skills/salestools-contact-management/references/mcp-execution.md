# 实际 MCP 调用与结果核对

企业研究与联系人管理共用此流程。通过当前宿主连接调用 MCP；不需要项目 checkout、npm 命令、数据库或本机 Token。此流程降低误调用，不能保证远端服务始终可用。

## 执行校验

每次实际调用前执行 `request`，收到原始 MCP 返回后执行 `result`，交回企业研究前执行 `handoff`。命令、依赖和输入格式见[校验脚本输入格式](validator-input.md)。

`ok:true` 不等于任务完成，必须同时读 `decision`：

| decision | 含义 |
| --- | --- |
| `dispatch_allowed` | 只允许发送本次请求。 |
| `waiting` | 等待任务。 |
| `needs_confirmation` | 按操作参考请用户选定候选。 |
| `partial` | 保留未完成范围。 |
| `not_found` | 只表示本次未取得记录。 |
| `validated` | 只表示返回契约通过。 |
| `ready_with_limits` | 只表示衔接路径有证据，不能证明现任或企业部署了软件。 |

result 阶段阻断只表示结果未通过检查，**不代表远端没有执行成功**。保留原返回和 operation_id，先回读核实，不自动重发写入。脚本无法运行时如实说明校验未执行。

## 调用前

1. 按用户目标选择主 skill 路由，只读本次操作需要的参考；企业研究需要找人时，先读[企业与联系人衔接](company-context.md)。只取本次需要的来源、产品、岗位与资料范围。
2. 查看当前连接实际公开的工具名称、描述和输入 schema。宿主支持延迟工具发现时先发现所需工具；工具仍缺失则说明阻塞步骤。不用本地实现、旧示例或相似工具名代替在线声明，也不自建带凭据的 HTTP 客户端绕过宿主。
3. 以在线 schema 核对必填项、类型、枚举、互斥字段和取值范围，只发送该工具支持的字段。业务参考补充 schema 没写的限制，例如 `include_unverified` 需要 keyword 和非空 query。参考与在线声明冲突时不猜参数，说明版本差异，按可核实的在线能力执行。缺少参数导致无法保留主体、范围、固定版本、只读或幂等要求时，停止该步骤并交回可用部分。
4. ID 取自用户明确指定且已回读核对的记录，或本轮实际返回结果，按下表区分用途。多个主体无法区分时才请用户选定，已有明确选择就复用。不把名称、示例占位符或另一个系统的 ID 填入标识字段。

| 标识 | 用途与核对 |
| --- | --- |
| credit_code / dossier_id / version_id | 已核实企业、研究档案与固定版本；写研究的 base_version_id 另取档案全局最新版本。 |
| entity_id / organization_id | 图谱人物或组织；通过库内搜索、档案及 confirmed 企业关联核对。CRM Account ID 不能代替。 |
| connection_id + account_id | 同一个 CRM 连接下的客户记录配对；组织代号、显示名称不自动等于连接 ID。 |
| run_id / brief_id / comparison_id / import_id | 各自任务或成果的返回标识；按对应状态或读取工具继续，不相互转换。 |

会写入或同步图谱的工具见[联系人边界](contact-limits.md#会写入或同步的操作)，不能按「搜索工具」一概当作只读。写工具要求版本或 operation_id 时按各自参考准备，不向只读工具附加这些参数。

## 调用后

先检查宿主调用异常和 MCP 的 isError，再检查业务失败码、status、found、warnings 与来源完整性。有 structuredContent 时从中读取业务对象；只有文本时，确为 JSON 才解析，保留原错误与警告。文本和结构化内容是同一结果的两种呈现，不算两份证据。

- 额度停用或无法核验时按[联系人边界](contact-limits.md#企业额度)处理。完整 M2 联系方式只能由用户在图谱 App 打开的网页查看，链接和兑换结果不加入脚本输入、聊天或研究交接。
- content 里的「操作已完成」不能覆盖结构化的 queued/running 或空 result。取得任务 ID 只表示受理；研究、拜访、比较按对应参考读取最终成果。
- found:false、空列表、部分来源失败、分页未完要分别说明，不能由此推出「此人不存在」「企业没有需求」或「已全部同步」。
- CRM 读取结果与图谱同步结果分别核对。需要图谱档案时再搜索并回读真实 entity_id；没有图谱映射时不手工新建或合并。
- 保存或维护成功后，按返回标识回读相关档案或导入结果，再称已生效。工具没有给出足够结果时标为待核验。

## 分页、失败与恢复

分页保持原主体、筛选、来源及固定快照或版本，只使用对应集合返回的 next_offset。网页续页保持 web_snapshot_id 并用 source:web；档案的证据、关系、待核实线索各走独立偏移。下一页重复或偏移不推进时停止，说明未取得完整范围。只需要局部证据时可以停止并注明已读范围。

| 情况 | 后续动作 |
| --- | --- |
| 纯只读调用临时网络失败 | 本次任务内至多原样重试一次；仍失败就保留已有结果并说明缺口。discover_contacts、get_company_key_people、创建任务及导入不归入此类。 |
| 写入、同步或创建请求超时、响应丢失 | 状态未知；有任务 ID 时先查询。只有工具明确支持幂等且确需恢复时，才用相同 operation_id 和完整原参数重放一次，不换 ID 试探。没有安全的查询或重放能力就报告未知。 |
| 参数错误、主体歧义、权限不足或版本冲突 | 修正已确认的参数或先回读主体、版本；不重复原错误，不切换身份或连接绕过，不自动覆盖更新。 |
| 限流、队列满、任务仍运行 | 尊重返回的等待提示；有界查询，用户每问一次进度只查一次。不给无限重试或后台通知承诺。 |
| failed / cancelled / PROCESS_RESTARTED | 返回失败原因与已完成部分；不把新任务当作自动恢复。用户要求重新执行后按对应参考创建。 |

研究接收联系人结果时，回传确认主体、来源、关系路径、证据时间、核实状态及未完成范围；结果只支持它实际证明的事实。详见[衔接约定](company-context.md)。
