# 证据边界

所有企业研究、简报、关键人、比较和追问共用本页。展示时把同类限定在结尾合并成一行，不在每条线索后重复，见[展示格式](display.md)。

## 信号能证明什么

| 证据 | 可以支持 | 不能证明 |
| --- | --- | --- |
| 招聘岗位 | 团队、岗位或软件、工程场景存在 | 采购意向、负责人是谁 |
| 融资 | 公司活跃度或时机信号 | 项目预算 |
| 行业标签 | 只作展示 | 机会判断依据 |
| 个人技能、历史任职、供应商或项目里的软件经历 | 需求探索输入，保留人物、公司和日期 | 企业当前部署，也不足以证明需要替换 |
| 竞品名称 | 存在比较对象的线索 | 企业正在使用或打算替换 |
| 工商登记职务 | 决策、管理与预算角色 | 参与软件选型 |
| 专利署名 | 研发线索；工程方向是按标题的关键词推断 | 现任或职务 |
| 职位 | 角色线索 | 决策权 |
| 同校、同公司、同场参会 | 可能的联系条件 | 熟识、上下级或可引荐 |
| CRM Owner | 记录负责人 | 认识客户或可引荐 |

机会等级是销售适配判断，置信度是证据可靠性，两者都不是成交概率。「待核实」不强行改为推荐。Owner、认识谁和联系人数量不参与机会排名，联系条件与产品机会分开展示。

## 时效与缺失

- 按返回的 `temporal_scope` 解释时效，`historical` 和 `unknown` 保留限定，不升级为当前情况。stale 资料可以展示，但要注明时效。
- `changed`、`unavailable` 及依赖它们的结论不能继续支撑新判断。`unavailable` 不等于客户没有需求。
- 「本次未查到」、没有直达链接、单个来源失败、没有档案或版本、「本次未发现 CRM 记录」，都不证明企业、需求或客户关系不存在。
- 任务处理范围完成，不等于采购需求已确认。`partial` 结果仍可以有有效事实，要说明覆盖范围和资料局限。
- 用户笔记标为用户提供，缺链接时不造链接。没有日历、邮件、纪要或互动证据时写未知，不编造客户态度、承诺或项目进度。
