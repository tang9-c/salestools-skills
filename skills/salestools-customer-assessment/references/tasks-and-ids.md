# 任务、标识与副作用

## 调用前看副作用

| 工具 | 副作用 |
| --- | --- |
| `start_company_research` | 保存研究版本，可能调用外部来源。 |
| `prepare_company_visit` | 保存共享简报。范围内某产品没有新版研究、研究超过 30 天或来自已退役的旧方法时，服务端会为这些产品补研一次，没有禁止补研或不保存的参数。 |
| `compare_company_opportunities` | 保存比较任务和结果，读取本地图谱，不调用模型、外部来源或 CRM，也不自动补研。 |
| `ask_company` | 可能补查外部来源，没有禁止补查的参数。 |
| `discover_contacts` | 可能按部署配置同步图谱，不能称为纯只读。 |
| `get_company_key_people` | 启用联系人图谱时会在后台同步公开人物。 |

用户明确要求「只读」「不保存」「不调用外部来源」时，不调用不符合限制的工具，改为读取已有成果和证据，在聊天里整理草稿，并说明它不是服务端成果。只限制外部调用但允许保存时，也不能假装 `prepare_company_visit` 可以禁止补研。缺少工具时说明受影响的环节，不模拟成果，不自动修改部署配置。

## operation_id 与重试

- 三个创建工具都需要 `operation_id`。同一逻辑请求保留完整参数和同一 ID。结果未知时先按已有任务 ID 查询；确需幂等重放时只原样重放一次。
- 改变范围、版本或用户明确要求重新生成时，用新 ID。不靠换 ID 绕过冲突、失败、队列或用户上限。
- 取得任务 ID 只表示已受理。研究完成后按返回的 `version_id` 回读；拜访和比较要读到非空 `result` 才能称为已生成。
- 等待要有界，用户每问一次进度只查询一次。可能需要数分钟时提前告知。
- `partial` 保留可用部分并说明限制。`failed`、`cancelled`、`PROCESS_RESTARTED` 不自动重发。队列或用户上限按实际错误说明，等待后查询，不循环提交。不承诺后台补齐或自动通知。

## 标识与读取

- 研究用 `version_id`，拜访用 `brief_id`，比较用 `comparison_id` 及企业标识。这些标识只用真实返回值，不猜、不混用，也不用最新资料替换历史引用。它们用于调用和回读，默认不在给用户的正文里展示，用户要求详情或排障时再给。
- 分页跟随 `next_offset`，`limit` 以在线 schema 为准，取到任务需要的内容就停止。
- get、list、status、evidence 类工具只读，不触发模型、来源重查或新版本。重读不会让历史结果变新。

## 共享范围

企业研究的常规任务状态和已发布成果可以被同一服务的其他已认证用户读取。`response_version:2` 的任务状态、草稿读取和取消仅限任务创建者。共享范围不授权向客户或外部人员发送材料。
